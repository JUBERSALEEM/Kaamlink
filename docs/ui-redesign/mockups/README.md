# Mockup renderer

The PNGs in this folder are **rendered from a structured layout**, not generated by
an image model: every string is drawn with the app's own font (Open Sans), icons come
from the Lucide glyph font, and Arabic specimens use Noto Sans Arabic. That means the
text in a mockup is exactly the text the implementation uses, which is what makes the
mockups usable as an implementation reference.

## Regenerate

```bash
python3 -m venv /tmp/mockup-venv
/tmp/mockup-venv/bin/pip install Pillow arabic-reshaper python-bidi
/tmp/mockup-venv/bin/python docs/ui-redesign/mockups/render_mockups.py
```

Requirements:

* `Resources/Fonts/OpenSans-*.ttf` and `Resources/Fonts/lucide.ttf` (in the repo)
* `docs/ui-redesign/mockups/fonts/NotoSansArabic-*.ttf` for the Arabic specimens
  (SIL OFL 1.1 — see `fonts/NotoSansArabic-LICENSE.txt`)
* Pillow is used *without* libraqm in CI-like environments; `mockup_kit.shape()`
  falls back to `arabic-reshaper` + `python-bidi`, which produces the same joining
  behaviour the Android text stack applies natively.

## Files

| File | Purpose |
|---|---|
| `mockup_kit.py` | tokens, fonts, icons, layout primitives and components |
| `render_mockups.py` | one function per screen; `SCREENS` lists the output order |
| `*.png` | rendered screens (720 × 1560 @2×, design system sheet is taller) |

The colour values in `mockup_kit.py` are asserted against
`Resources/Styles/Colors.xaml` by `tools/verify-ui-redesign.py`, so a palette change
fails verification until the mockups are regenerated.
